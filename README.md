# Расписание занятий (консольное приложение на Kotlin)

Программа читает файл с расписанием, проверяет каждую строку и печатает занятия или ошибки.

Автор: Коновалов Матвей Никитич.

## Сборка и запуск

Команды выполняются из корня проекта (там, где `gradlew` и папка `samples`). Нужен JDK 25.

```bash
bash ./gradlew build :app:installDist
./app/build/install/schedule/bin/schedule period --file samples/clean.txt --from 2026-09-28 --to 2027-05-13
./app/build/install/schedule/bin/schedule type   --file samples/dirty.txt --type EXAM
./app/build/install/schedule/bin/schedule errors --file samples/dirty.txt
```

На Windows: `.\gradlew.bat ...` и `schedule.bat`. Проверка по эталонам: `python tools/verify.py`.

## Как обрабатываются данные

1. Файл читается построчно (`forEachScheduleLine`), номера строк начинаются с 1.
2. Каждая строка отдаётся в `Parser.getSessionFromString`, он возвращает один из результатов:
   - `State.Result` — строка корректна, внутри готовое занятие;
   - ошибка (`ErrorState`) — строка отклонена, внутри причина в виде данных, а не текст и не исключение.
3. Ошибочная строка не останавливает чтение, программа идёт к следующей.
4. Файл всегда проверяется целиком, даже если занятие не попало в фильтр.
5. Результат печатается через `println`, а итог (`Total` или `Rejected`) после чтения всего файла.

Формат строки: `date|type|topic|location|teachers`

| Команда | Что делает |
|---|---|
| `period` | занятия с датой от `--from` до `--to` включительно, итог `Total: N` |
| `type` | занятия одного типа вместе с преподавателями, итог `Total: N` |
| `errors` | ошибки по строкам файла и итог `Rejected: K of M` (K отклонено из M строк) |

Коды завершения: `0` — отклонённых строк нет, `1` — есть отклонённые строки (в том числе в `period` и `type`), `2` — неверные аргументы или файл не прочитался.

## Как проверяются данные

Проверка идёт в два уровня.

**1. Парсер — формат строки.** Проверки выполняются по порядку, на строку выдаётся только первая найденная ошибка:

1. есть ли в строке `|`;
2. полей ровно 5;
3. нет ли пустого или состоящего из пробелов поля;
4. дата вида `YYYY-MM-DD`, существует, год `0001..9999`;
5. тип один из `LECTURE`, `PRACTICE`, `EXAM`, `CANCELLED` (регистр важен);
6. у `EXAM` не меньше двух преподавателей (считаются только непустые имена, не равные `-`);
7. нет пробела в начале или конце поля;
8. дальше строка превращается в занятие, и её проверяет модель.

**2. Модель — классы `Lecture`, `Practise`, `Submitting`, `Cancellation`.** Правила проверяются в `init`, поэтому занятие нельзя создать неправильным, даже если вызвать конструктор напрямую (не через файл). При нарушении бросается `SessionException` (наследник `IllegalArgumentException`). Парсер ловит это исключение и превращает его в ошибку строки.

Правила модели:

- год даты от 1 до 9999;
- тема не пустая и не из одних пробелов;
- в теме, месте и именах нет управляющих символов (в том числе табуляции), нет пробела в начале или конце;
- место не пустое и не `-`;
- у лекции и практикума минимум 1 преподаватель, у сдачи (`EXAM`) минимум 2;
- имя преподавателя не пустое и не `-`, повторов нет (`Ivanov` и `ivanov` разные);
- у отмены (`CANCELLED`) есть только дата и тема, в файле место и преподаватели должны быть `-`.

Данные не исправляются автоматически: пробелы не обрезаются, регистр не меняется, повторы не удаляются.

## Сообщения об ошибках

Формат: `line N: <причина>`, где `N` — номер строки в файле.

| Причина | Сообщение |
|---|---|
| нет `\|` | `line N: invalid field separator` |
| не 5 полей | `line N: got 6 fields, expected 5` |
| пустое поле | `line N: empty required field "date"` |
| плохая дата | `line N: invalid date "2026-13-45"` |
| неизвестный тип | `line N: unknown session type "SEMINAR"` |
| мало преподавателей у сдачи | `line N: type "EXAM" requires at least 2 teachers, got 1` |
| пробел в начале или конце поля | `line N: outer whitespace in field "topic"` |
| управляющий символ | `line N: control character in field "topic"` |
| у отмены место или преподаватели не `-` | `line N: cancelled session field "location" must be "-"` |
| плохое место | `line N: invalid location "-"` |
| плохое имя преподавателя | `line N: invalid teacher "-"` |
| повтор преподавателя | `line N: duplicate teacher "Ivanov"` |

Имена полей: `date`, `type`, `topic`, `location`, `teachers`.

Значения внутри кавычек экранируются: `\` становится `\\`, `"` становится `\"`, управляющие и не-ASCII символы становятся `\uXXXX`. Так испорченные данные не добавят в сообщение перевод строки или русский текст. Сами значения в модели не меняются.

Если в строке несколько ошибок, показывается первая по порядку проверок. Например:

- `2026-13-45|SEMINAR|Topic|Room 1|Ivanov` — ошибка даты;
- `2026-10-05|EXAM|Topic|Room 1|Ivanov,Ivanov` — ошибка повторного имени;
- `2026-10-05|EXAM|Topic|Room 1|Ivanov,-` — `requires at least 2 teachers, got 1`, потому что `-` не считается преподавателем.

Ошибки запуска (код `2`): `Invalid arguments` — неверные аргументы, `Cannot read file` — файл не найден или не читается.

## Решения по модели

**Почему обычный `class`, а не `data class`.** У `data class` есть `copy()`, через который можно создать объект с неверными данными в обход проверок. Обычный класс такой лазейки не имеет. Автоматический `equals` тоже не нужен: одинаковые занятия по заданию хранятся отдельно.

**Защита списков преподавателей.** В конструкторе список копируется (`toList()`), в свойстве хранится копия. Поэтому `names.clear()` у исходного списка занятие не затрагивает. Наружу свойство отдаётся с типом `List`, у которого нет `add` и `remove`. Реестр так же отдаёт из `all()` копию, а не свой внутренний список.

**Реестр с журналом.** `AuditedSessionRepository` объявлен как `SessionRepository by delegate`: хранение отдаётся внутреннему реестру, а обёртка переопределяет `add` и `addAll` и после успешного вызова записывает событие (операция и количество занятий). `all()` событий не создаёт. `getLogsInfo()` возвращает суммарные значения: `sessions`, `added`, `audit events`.

**Почему переопределить только `add` недостаточно для `addAll`?** При `by delegate` Kotlin сам создаёт методы, которые просто вызывают такие же методы `delegate`. Поэтому `addAll` обёртки уходит прямо в `delegate.addAll`, а внутренний реестр ничего не знает про обёртку и её `add` не вызывает. Без отдельного `override fun addAll` пакетное добавление осталось бы незамеченным и в журнал бы не попало.

## Попытки сломать модель

| Попытка | Что защищает |
|---|---|
| пустая тема | проверка при создании (`init`) |
| год `0` или `10000` | проверка при создании |
| лекция без преподавателей | проверка при создании |
| сдача с одним преподавателем | проверка при создании |
| сдача с двумя одинаковыми | проверка при создании |
| изменить исходный список после создания | защита коллекции (копия в конструкторе) |
| изменить состояние через выданный список | защита коллекции (тип `List` без изменяющих методов) |
| обойти проверки через `copy` | устройство типа (обычный `class`, `copy()` нет) |

Тесты лежат в `app/src/test/kotlin/schedule`: `SessionTest`, `ParserTest`, `SessionRepositoryImplTest`, `AuditedSessionRepositoryTest`, `CliTest`.
